# Video-led landing patterns

This public package documents reusable patterns only. It intentionally excludes local HTML studies, generated footage, screenshots, fonts, prompts, and brand material. Build every new result from an original first frame.

## 1. Motion control

A dark, art-directed image-to-video loop can carry an entire hero when navigation, copy, actions, and the video control stay live HTML above it. The crucial separation is: footage carries atmosphere; the DOM carries information and access.

## 2. Deliberate motion

Start with a production-quality raster first frame. Lock the camera, preserve the composition and UI negative space, then move only the object whose motion proves the page's idea. Do not ask an image-to-video model to invent a new scene, a new camera move, or text.

## 3. Full-viewport world

The video should be the first screen's world, not a card inside a generic product layout. Place a contrast veil only where copy needs it. Keep the headline, one supporting sentence, one primary action, and one real control in the DOM.

## 4. External video handoff

When no authorized video API is available, the Agent still creates the first frame and the image-to-video prompt. The user generates an MP4 through an image-to-video service they can access, then imports it back. This is a source substitution, not a quality downgrade.

## Reusable checks

Before handoff, confirm the first viewport is a video world rather than a contained card; text remains readable without being baked into footage; the poster and reduced-motion fallback work; and the video is a real playable MP4 inspected at first, middle, and last frame.
